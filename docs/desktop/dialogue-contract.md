# 桌面化 · 对话文案契约(issue #16)

> 本文是文案生产票(#17)的唯一输入。DeepSeek(或任何文案生产者)只拿本文 + `dialogues.schema.json`,无需追问即可产出格式合规文案。**本文不含文案正文**,正文一律落在 `docs/desktop/dialogues.json`。

## 1. 机器可读契约

- JSON Schema:`docs/desktop/dialogues.schema.json`(本文件的字段定义是其人话版)
- 文案落盘:`docs/desktop/dialogues.json`(top-level `{ "version": "1.0.0", "messages": [...] }`)
- 校验:字段名、枚举值、id 唯一性以 schema 为准;文案语气以 §4 人设卡为准

## 2. 消息对象 schema(字段表)

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `id` | string | ✓ | 全局唯一。命名 `<类前缀>_<语义或序号>`:分镜 `sb_*`、局内推送 `ep_*`、结局对话 `ed_<结局枚举>_*`、彩蛋 `egg_*` |
| `category` | enum | ✓ | `storyboard`(开场回忆杀分镜)/ `push`(局内事件锚推送)/ `ending`(结局对话)/ `tooltip`(系统彩蛋) |
| `contact` | enum | ✓ | `boss`(甲方老总)/ `hr`(HR)/ `wang`(老王)/ `system`(系统)/ `player`(玩家,仅状态,见 §4.5) |
| `text` | string | ✓ | 消息正文。≤60 字为宜(气泡可读性);分镜条目可放宽到 80 字 |
| `trigger` | object | ✓ | 见下 |
| `orderInGroup` | number | ✓ | 组内顺序(分镜帧序 / 结局组内对话序),从 1 起 |
| `interruptible` | boolean | push 类必填 | 该条是否允许在玩家操作中弹 toast 打断;`false` = 仅红点+提示音,不打断 |
| `effects` | object | — | `{ "sound": "ding"\|"urgent"\|"none"`, `"badge": boolean`, `"pin": boolean }`,缺省全 false/none |

`trigger` 对象:

| 字段 | 类型 | 必填 | 说明 |
| :--- | :--- | :--- | :--- |
| `type` | enum | ✓ | `event`(事件锚)/ `time`(时间锚兜底)/ `ending`(结局锚)/ `static`(静态展示:分镜/彩蛋) |
| `event` | enum | event 型必填 | 见 §3.1 锚点枚举 |
| `atSec` | number | time 型必填 | 自 16:56:00 起的相对秒(240s 引信坐标) |
| `ending` | enum | ending 型必填 | `win` / `fuse` / `row1`…`row5` |
| `once` | boolean | — | 默认 `true`:每局最多触发一次 |

## 3. 触发锚点枚举表

### 3.1 事件锚(与引擎既有触发面一一对应,不得虚构引擎不存在的事件)

| 枚举值 | 引擎事实(消费点) | 建议时机 |
| :--- | :--- | :--- |
| `first_manual_switch` | 首次 Tab 切入 Sheet2(sheetSlice) | 查表期开场,甲方催进度 |
| `first_edge_a` | 玩家动 G 列后首次 Edge A 连坐(penaltySlice.row4Imbalanced 首次惩罚落地) | 老王式说明/甲方甩锅 |
| `row5_stuck` | Row5 首次假死进窗(row5Phase=stuck) | 高压期打断 |
| `row5_stuck_repeat` | 第二次及以后假死 | 决战期压迫 |
| `fuse_60s` | 引信剩余 <60s(tick) | 决战期开场 |
| `fuse_30s` | 引信剩余 <30s(嘀嗒三级加急同步) | 决战期收尾 |
| `first_defuse` | 首个模块拆除(defuseModule) | 正向反馈 |
| `skill_format_brush` | 首次使用格式刷(skillSlice) | HR/甲方吐槽 |
| `skill_freeze_pane` | 首次使用冻结窗格(skillSlice) | 同上 |
| `row8_trap` | 首次点击 Row8 禁操(全场 -30s) | 甲方暴怒/HR 补刀 |

### 3.2 时间锚(兜底)

- 仅当对应事件锚整局未触发时,由 `atSec` 兜底播出;坐标 = 16:56:00 起算的相对秒
- 用途:保证 8–10 条/局的节奏下限(参考 pacing 票 #19 的节奏表)

### 3.3 结局锚(映射引擎 `endReason` 既有 4 条路径 × 凶手模块)

| 枚举值 | 引擎 endReason 文案 | 对话组 |
| :--- | :--- | :--- |
| `row1` | 跨部门汇总 当场爆炸。 | Row1 组 |
| `row2` | 防欠薪网关 当场爆炸。 | Row2 组 |
| `row3` | 乱码考古 当场爆炸。 | Row3 组 |
| `row4` | 平账脚本 当场爆炸。 | Row4 组(账目/钱侧重) |
| `row5` | 重启仪式 当场爆炸。 | Row5 组(「又双叒挂了」侧重) |
| `fuse` | 17:00 了,引信烧完,全表爆炸。 | 引信组 |
| `win` | 17:00 准点跑路,下班! | 胜利组 |

每组 2–4 条;组内 `orderInGroup` 决定气泡先后;结局对话展示顺序由 pacing 票(#19)定稿。

### 3.4 静态展示(storyboard / tooltip)

- 分镜:`storyboard` 类型不挂 trigger(开场动画播),只按 `orderInGroup` 排帧;8–12 条、总时长 ≤25s
- 彩蛋 `tooltip`:`trigger.type = "static"`,消费点 = 任务栏图标 tooltip / 聊天窗口标题栏 / 「已拉黑」状态条等 UI 挂点,不进消息流

## 4. 人设卡(语气基准)

### 4.1 甲方老总 `boss` — 暴躁金主

- 动机:防拖欠尾款、催进度、甩锅;永远觉得慢
- 语气:短句、感叹号、重复施压;偶尔拿「尾款」当武器
- 基准句(供校准,不要求复用):
  - 「进度呢?我要的不是进度,是结果!」
  - 「系统又挂了?尾款别想!」
  - 「五点前给不了我答复,合同就是废纸!」

### 4.2 HR `hr` — 圆滑补刀

- 动机:制度、考勤、流程;永远在微笑着补刀
- 语气:称呼亲昵 + 制度条款;先扬后抑
- 基准句:
  - 「辛苦啦~对了,17:00 下班打卡别忘哦。」
  - 「加班申请单走 OA 了,审批人:离职中的老王。」
  - 「公司文化是家的文化~家会爆炸吗?不会的,加油!」

### 4.3 老王 `wang` — 丧系前架构师(已拉黑)

- 动机:已离职、已拉黑、文档是唯一遗产;黑话里藏真心
- 语气:低能耗、惜字、偶尔冒一句真情;**默认消息不送达**(见 §4.5)
- 基准句:
  - 「别发挥。按文档做。」
  - 「我不是改不动,是不想改。」
  - 「G28 写着:没有黑历史,都是被人陷害的。」

### 4.4 系统 `system` — 无情绪的祸

- 动机:搬运行程/监控/灾情通报;与 GDD §3.4 三条播报同调性
- 语气:【系统提示】开头,冷静陈述荒诞事实
- 基准句:
  - 「【系统提示】您的离职交接人已将您拉黑。」
  - 「【系统提示】检测到 0 条道歉。」

### 4.5 玩家 `player` — 沉默牛马(特殊:不发言)

- 玩家**不产生任何文本消息**;聊天列表中玩家侧仅呈现「已读」回执、`对方正在输入…` 状态条
- 契约层面:`contact: "player"` 仅允许出现在 `storyboard` 分镜(入职回忆杀里「你」的提问气泡),局内与结局一律禁用

## 5. 语气红线(校验清单)

1. 不出现解谜必需信息(聊天是氛围+轻度钩子,硬线索只在 Sheet2 手册)
2. 不得嘲讽玩家操作(压迫感来自事件本身,不来自骂玩家)
3. 每条 ≤60 字(分镜 ≤80);单条单语气,不混联系人
4. 制度梗/尾款梗/祖传梗可复用,网络烂梗(如谐音烂梗)不进正文
5. 结局组不出现「复活/重开吧」元话语(重开由 UI 承担)
