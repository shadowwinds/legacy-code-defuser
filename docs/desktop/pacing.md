## 3. 节流与密度

- 每局 toast 上限 **6 条**(48 条文案里的 push 10 条,事件锚 + 档位过滤后实际弹出 ≤6)
- **15s 节流窗**:任意 15s 内最多 1 条 toast;超出的自动降 C 档红点(防 40–50s 扎堆:first_manual + first_edge_a + row5_stuck 可能连发)
- 静态彩蛋(tooltip 类)不占 toast 预算
- 0:00–0:40 熟悉期 **0 条新推送**(系统播报除外)——留给玩家摸 Row4

## 4. 结局对话 × EndOverlay 顺序(决策)

1. 终局瞬间:结局组气泡按 `orderInGroup` **快速吐入聊天流**(每条间隔 400ms,营造连环轰炸)
2. 首条气泡后 **0.8s** EndOverlay 淡入(既有 win98 弹窗)
3. 弹窗之下聊天窗口保持可见可回看(遮罩接管 pointer-events,不可交互)
4. 理由:先对话后结算 = 先情绪冲击后系统归档;同时弹出会互相抢焦点
