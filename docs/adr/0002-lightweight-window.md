# ADR-0002 · 聊天叙事壳采用「轻量窗口」而非窗口管理器

* **Status**: Accepted
* **Date**: 2026-10-24
* **Deciders**: 项目所有人(charting 会话 Q4)+ AI 结对助手

## Context

v1.1 桌面化里程碑要把「Windows 桌面」包在 Excel 外层:任务栏、聊天浮层、Toast、开场动画。一个诱人的方向是做成「真窗口」——聊天窗可拖拽、可与 Excel 遮挡、可切聚焦,拟真度和自由度都更高。但游戏本体是 240 秒倒计时的解谜,ExcelShell 是全屏高密度交互面(拖列宽/悬停批注/下拉),聊天只是氛围层。

## Decision

**轻量窗口**:Excel 永远独占全屏;聊天浮层固定位置、不拖拽、不遮挡 Excel、不参与焦点管理,可收起为任务栏图标(红点提示未读)。Toast 点击跳聊天而非直接展开窗口。

## Consequences

* **不做**窗口管理器:没有 z-index 战场、没有拖拽状态机、没有焦点丢失导致的误操作——Excel 交互面(尤其 D 列拖拽、批注 hover)行为可预测。
* 聊天的「存在感」由任务栏红点 + Toast 提供,窗口本体只是点击后的阅读面;若未来玩家反馈想要真窗口,需重开 ADR(成本:拖拽 + 遮挡 + 聚焦三套状态机)。
* 窄屏降级形态(桌面壳如何收起)未定,留待桌面化实现票验证(Fog:多局记忆/占位 App 同)。
* 此决策不可逆点:ExcelShell 的 DOM 结构假设「自己独占视口,桌面元素挂 body 层」——若实现期破坏此假设,回退成本高。
